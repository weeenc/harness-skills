# API Mock 数据生成 — harness-api-mock

> **技能标识**: `harness-api-mock`
> **使用场景**: "接口先定好、数据先 mock 出来"——后端未就绪时让前端/联调先行
> **定位**: 服务于联调与测试——mock 数据必须**忠于接口协议**，否则联调时假数据反而误导

## 它做什么？

按 `.harness/wiki/接口协议.md`（或 change.md 的「契约影响 · REST」）生成 **mock 数据与 mock 服务**，使前后端可并行开发、联调不阻塞。后端接口未实现时，用 mock 把契约固定下来，让前端可先行开发，让测试可先跑通。

## 什么时候用？

- 前后端并行开发，后端接口未就绪
- change 定义新接口，需要先行验证前端/链路
- E2E/集成测试需要稳定的测试数据（脱离真实下游依赖）

## 核心机制

### 执行流程

```
Step 1: 提取契约（路径 / 方法 / 请求参数与校验 / 响应结构 / 错误码 / 依赖）
    ↓
Step 2: 生成 mock 数据（多种形态：成功/空/边界/错误/鉴权）
    ↓
Step 3: 落地 mock 服务（内嵌 mock server / mock 数据文件 / 网关代理 mock）
    ↓
Step 4: 校验（响应过契约校验 + 至少一个真实请求打通）
```

### mock 数据分支（分支齐全）

| 分支 | 示例数据 | 用途 |
|------|---------|------|
| 正常成功 | <符合契约的完整响应> | 主流程 |
| 空数据 | <空列表/空对象> | 空态 UI |
| 边界值 | <最大/最小/超长/特殊字符> | 边界校验 |
| 错误分支 | <业务错误码 + 错误信息> | 错误处理 |
| 鉴权失败 | <401/403 响应> | 权限拦截 |

### 落地方式（按项目能力选择）

1. **内嵌 mock server**：轻量脚本/服务（如 mock 框架），按契约文件返回数据
2. **mock 数据文件**：JSON/fixture 文件，供前端直接 import 或测试加载
3. **网关/代理层 mock**：在开发网关配置 mock 路由

产出 `.harness/changes/<id>/api-mock.md`：接口→mock 数据文件的映射表 + 启动方式。

## 纪律

- **忠于契约**：mock 字段名、类型、枚举值**逐字对照接口协议**，不自由发挥；响应必须包含真实接口会返回的字段（含 `code`/`message`/`data` 包裹结构，按项目约定）
- **分支齐全**：不只 mock 成功分支，错误/边界分支也要覆盖（前端才测得到）
- **可复现**：随机数据使用固定种子（seed），测试不 flaky
- **标注状态**：mock 与 real 接口在文档中明确区分（`mock` / `real`），防止误以为接口已实现

## 为什么需要它？

| 问题 | 解法 |
|------|------|
| 后端没做好，前端干等 | mock 固定契约，前后端并行开发 |
| mock 数据瞎编，联调踩坑 | 字段/类型/枚举逐字对照接口协议 |
| 只有成功分支，错误处理测不到 | 成功/空/边界/错误/鉴权五类分支全覆盖 |
| 随机数据导致测试 flaky | 固定种子保证可复现 |
| 误以为 mock 接口已实现 | 文档标注 `mock` / `real` 状态 |

## 完成标志

- 契约接口均已生成 mock 数据（含成功/空/边界/错误/鉴权分支）
- mock 服务可启动，至少一个真实请求验证通过
- `api-mock.md` 已落盘，接口 mock 状态已标注
