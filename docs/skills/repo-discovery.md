# `repo-discovery`：多仓库发现与需求路由

当一个业务工作空间包含独立的前端、后端或契约仓库时，先建立仓库地图，再进入需求分析。工作空间根目录可以没有 `.git`，但每个代码仓库必须有自己的 Git 根和 `.harness/`。

技能会维护 `.harness/repo-map.yaml`，记录仓库路径、职责、技术栈、契约发布/消费关系和门禁命令。协调层可以是共同父目录，也可以是与业务仓库同级的独立仓库；同级布局从协调层检查共同父目录下的直接兄弟仓库，并以 `../<repo-dir>` 形式登记路径。目录名不决定仓库职责；如果候选过多或职责无法判断，先要求用户确认。它把“支付对账超时”这类需求路由到后端服务、前端页面和可能的契约仓库，并要求人确认多仓影响面。

建议为工作空间增加一个独立的 coordinator Git 仓库，用来版本化 `repo-map.yaml`、workspace 级变更卡和联合门禁脚本。前后端代码仍保持各自 Git 历史，不需要合并成 monorepo。
