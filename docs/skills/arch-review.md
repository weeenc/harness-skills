# 架构体检 — arch-review

> **技能标识**: `arch-review`
> **使用场景**: 需要扫描代码库，发现架构摩擦点，生成可视化报告

## 它做什么？

扫描代码库，发现"浅模块"和架构摩擦点，生成可视化报告，然后逐个打磨改进方案。

## 什么时候用？

- 代码库变得难以维护，需要架构体检
- 频繁在某个模块改 Bug，需要排查
- 新成员加入，需要了解架构现状
- 直接调用 `/arch-review`

## 工作流程

### Step 1: 确定范围

先确定范围再扫描——YAGNI。关注最近频繁变更的模块，它们是投入产出比最高的地方。

### Step 2: 扫描

分析代码库，发现：
- **浅模块** — 只封装但没有抽象，只是"换了个地方写代码"
- **循环依赖** — 模块间相互引用
- **上帝类** — 一个类做了太多事
- **过度耦合** — 模块间耦合度过高
- **重复代码** — 相同逻辑散布多处

### Step 3: 生成报告

生成可视化 HTML 报告，包含架构问题的分类和分布。

### Step 4: 打磨改进

逐个打磨改进方案，每个方案都经过：
- 问题描述
- 影响评估
- 改进方案
- 工作量估计
- 优先级排序

## 为什么需要它？

| 问题 | 解法 |
|------|------|
| 代码库越来越乱，但不知道哪里最需要改 | 扫描发现"浅模块"和摩擦点 |
| 架构问题不可见 | 可视化报告，一目了然 |
| 不知道从哪里开始改 | 按优先级排序，从投入产出比最高的开始 |
| 改进方案不明确 | 逐个打磨，每个方案都经过评估 |
