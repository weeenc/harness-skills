# 需求打磨 — harness-me / harnessing

> **技能标识**: `harness-me`（入口）、`harnessing`（引擎）
> **使用场景**: 当用户要求"帮我理清需求"、"分析这个方案"、"这个设计有没有漏洞"、"帮我打磨一下"

## 它做什么？

一场"灵魂拷问"式的对话，帮你把模糊的需求/方案/设计打磨到能落地的程度。

### 核心机制

```
用户输入模糊想法
    ↓
harness-me 调用 harnessing
    ↓
harnessing 一次只问一个问题
    ↓
用户回答，打开新的问题分支
    ↓
沿决策树推进
    ↓
输出需求总结卡片
```

### 核心原则

**一次只问一个问题。** 同时抛出一堆问题会让人不知所措。

**不要急着给答案。** 你的任务是问更好的问题，而不是替用户想方案。

**沿决策树分支推进。** 每个答案会打开新的问题分支，跟随它。

## 什么时候用？

- 需求不清晰，需要打磨
- 方案不确定，需要分析漏洞
- 设计有疑问，需要推理
- 直接调用 `/harness-me` 或 `/harnessing`

## 为什么需要它？

| 问题 | 解法 |
|------|------|
| 需求模糊，AI 猜错了方向 | 一次只问一个问题，逐步收敛 |
| 方案有漏洞没发现 | 灵魂拷问，暴露盲区 |
| 设计决策没有充分推理 | 沿决策树推进，每个分支都覆盖 |
| 用户自己也没想清楚 | 通过提问帮用户厘清思路 |

## 输出

需求总结卡片，包含：
- 明确的需求描述
- 关键约束
- 待决策事项
- 下一步建议
