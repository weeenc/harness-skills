# ⑤ CI 门禁 — unit-test-ci

> **流水线阶段**: ⑤ 第五步
> **技能标识**: `unit-test-ci`
> **输入**: 通过 ④ 评审的完整变更
> **出口门禁**: 所有 CI 阶段全绿

## 它做什么？

机械化执行全量质量门禁——把约束从"靠人记"变成"靠机器验"。

### CI 流水线阶段

```
stage-1  编译检查
stage-2  静态分析（代码规范）
stage-3  架构约束
stage-4  单元测试 + 覆盖率
stage-5  安全扫描
```

任一阶段失败即红灯，禁止放行。

## 什么时候用？

- 代码已通过专家评审，需要机器验证
- 流水线第五步，在专家评审之后

## 各阶段详解

### 编译检查

确保代码可以编译通过，没有语法错误和类型错误。

### 静态分析

运行代码规范检查工具，确保符合编码规范。具体工具（`{{LINT_TOOL}}`）和配置因语言/框架而异，详见 `apply-harness` 参数表。

### 架构约束

确保代码符合工程结构规范。架构约束工具（`{{ARCH_TEST_TOOL}}`）和检查规则因语言/框架而异，详见 `apply-harness` 参数表。

### 单元测试 + 覆盖率

- 运行全量单元测试
- 检查覆盖率 ≥80%（核心逻辑）

### 安全扫描

扫描已知漏洞和安全隐患。

## 核心原则

> **机械化执行：编译 → 静态分析 → 架构约束 → 单元测试+覆盖率 → 安全扫描。任一检查失败即红灯，不放过。**

## 出口门禁

- [ ] 编译通过
- [ ] 静态分析通过
- [ ] 架构约束通过
- [ ] 全量测试通过
- [ ] 覆盖率 ≥80%
- [ ] 安全扫描通过
