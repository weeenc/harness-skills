# 上下文交接 — handoff

> **技能标识**: `handoff`
> **使用场景**: 当前对话上下文快满了，需要开新对话继续工作

## 它做什么？

将当前对话的工作上下文压缩为一份交接文档，下一个对话可以直接读取续接。

## 什么时候用？

- 当前对话上下文快满了，需要开新对话
- 一个变更跨越多个编码周期
- 需要把工作交给另一个开发者或 AI 实例

## 工作流程

### Step 1: 整理上下文

- 当前变更的状态（change.md 中的状态）
- 已完成的工作
- 待完成的工作
- 关键决策和原因
- 当前遇到的问题

### Step 2: 生成交接文档

- 压缩为结构化文档
- 包含所有关键信息
- 下一个人可以直接读取续接

### Step 3: 保存

- 保存到 `.harness/changes/<id>/handoff.md` 或其他指定位置

## 交接文档包含什么？

```
- 项目名称
- 当前变更 ID
- 变更状态
- 已完成的工作
- 待完成的工作
- 关键决策
- 当前问题
- 下一步建议
- 相关文件列表
```

## 为什么需要它？

| 问题 | 解法 |
|------|------|
| 新对话不知道之前做了什么 | 交接文档包含完整上下文 |
| 决策原因丢失 | 记录关键决策和原因 |
| 重复工作 | 交接文档明确"已完成"和"待完成" |
| 上下文碎片化 | 交接文档串联多轮对话 |
