# 质量闸门与报告 — harness-quality

> **技能标识**: `harness-quality`
> **使用场景**: "质量达标了吗？能不能放行？"——需要客观、可追溯、人签字的质量判定
> **定位**: 在 `/unit-test-ci` 机械化执行之上做客观判定 + 可追溯 + 人签字

## 它做什么？

跑真实 check → 对照质量目标 → 出可核对的报告 → **人签字放行**。

> **与 `/unit-test-ci` 的分工**：`unit-test-ci` 是机械化执行全量门禁（编译/静态分析/架构约束/测试/安全），本技能在其之上做**客观判定 + 可追溯 + 人签字**——一切判定来自真实数据，AI 只整理报告，**放行由人**。

## 立身之本

**一切判定来自客观数据**：覆盖率数字来自覆盖率工具、E2E 覆盖来自 flow→test 映射 + 真跑结果、lint 来自退出码。**AI 只负责把这些数据整理成报告，不参与"达标与否"的判定**，放行由人。

> ⛔ 绝不允许出现的行为：
> - 用"我看了一下代码，测试挺全的"这类判断替代真实数据
> - 用上一次的结果冒充本次
> - 命令没跑通却按通过处理
> - 覆盖率没测量却写一个数字
> - **量不到就如实写"未测量"**——与"无命令可跑 → 该项不判定"是同一条纪律

## 核心机制

### 前置：两份真源

| 文件 | 作用 | 缺失时 |
|------|------|--------|
| `.harness/rules/开发流程规范.md` + 语言包 `unit-test-ci` 技能内的命令段 | **怎么量**（TEST_CMD / COV_CMD / LINT_CMD / ARCH_TEST_CMD / SECURITY_CMD 等） | 中止，提示先跑 `/apply-harness` 或 `/unit-test-ci` |
| `.harness/quality-targets.yml` | **目标值**（覆盖率阈值、lint 阈值、flow→test 覆盖要求） | 用默认值创建，提示人类确认（目标调整属人类决策，AI 不得自行放宽） |

### 执行流程

```
Step 1: 锁定范围（按变更定位规则定位 change，或 git diff / 版本区间）
    ↓
Step 2: 跑真实 check（机械执行，记录真实退出码与原始输出）
    ↓
Step 3: flow→test 映射矩阵（每条 AC 必须有直接对应的测试）
    ↓
Step 4: 出报告 .harness/changes/<id>/quality-report.md
    ↓
Step 5: 人签字放行（同意 / 拒绝并给理由）
```

### flow→test 映射矩阵

对 `change.md` 的**每条验收标准 AC** 建立映射：

| 业务流 / AC | 触发入口 | 对应测试（文件:用例） | 状态 |
|-------------|---------|---------------------|------|
| AC-1: <描述> | <接口/入口> | <测试文件>:<用例名> | 🟢 已覆盖 / 🔴 无测试 / ⚠️ 仅间接覆盖 |

- 每条 AC 必须有**直接对应的测试**（单元/集成/E2E 均可），无测试 → 🔴 红灯
- 把 AC 清单与测试文件列表逐条**对账**，**漂移即红灯**——实现里的行为在 AC 中没有、或 AC 中的行为没有测试，都算漂移

### 报告结构

```markdown
# 质量报告: C-NNN
## 范围
## 客观数据        # 检查项 | 真实结果 | 目标 | 判定（含"未测量"项）
## 达标判定        # 是否全部达标 + 未达标项清单与差距数据
## 放行签字        # [ ] 我（人类）确认数据属实 / [ ] 拒绝放行，理由
```

## 什么时候用？

- change 到达 `ci` 状态，放行进入 `verifying` 之前
- 全项目质量体检（指定版本区间作为范围）
- 需要客观回答"质量达标了吗 / 能不能放行"

## 为什么需要它？

| 问题 | 解法 |
|------|------|
| "质量还行"没有依据 | 全部判定来自真实检查数据 |
| 测试覆盖了但没人对账业务流 | flow→test 映射矩阵逐条核对 AC |
| AI 擅自判定达标 | 放行签字只能由人类完成 |
| 命令没跑通也能蒙混过关 | 量不到就写"未测量"的硬纪律 |

## 完成标志

- 报告已落盘 `.harness/changes/<id>/quality-report.md`，全部数据来自真实运行
- flow→test 映射已逐条对账，漂移已红灯
- 已获得人类签字（放行或拒绝），未代签
