# ⑥ 部署验证 — deploy-verify

> **流水线阶段**: ⑥ 第六步 · 收口
> **技能标识**: `deploy-verify`
> **输入**: 通过 ⑤ CI 的构建
> **产出**: `.harness/changes/<id>/verify.md`
> **出口门禁**: 冒烟 + 健康检查通过、有回滚预案

## 它做什么？

部署后冒烟测试、健康检查、关键链路验证，确保变更在真实环境可用且可回滚。

## 什么时候用？

- CI 门禁已通过，需要部署到测试/生产环境验证
- 流水线第六步，最后一步

## 工作流程

### Step 1: 准备环境

确认部署目标环境就绪。

### Step 2: 健康检查

- 应用健康检查端点是否返回 UP
- 数据库连接是否正常
- 外部依赖是否可达

### Step 3: 冒烟测试

- 运行关键的冒烟测试用例
- 确认核心功能可用

### Step 4: 关键链路验证

- 验证核心业务链路通
- 验证降级链路通

### Step 5: 回滚预案

- 确认有回滚方案
- 确认回滚步骤清晰

## 核心原则

> **"CI 绿"不等于"线上可用"。确认健康检查 UP、核心链路通、降级链路通、有回滚预案。**

## 为什么需要部署验证？

| 误区 | 真相 |
|------|------|
| "CI 过了，部署肯定没问题" | 环境不同，配置不同，依赖不同 |
| "测试环境测过了" | 生产环境有真实流量、真实数据 |
| "功能能跑就行" | 降级路径、超时、容错需要验证 |

## 出口门禁

- [ ] 健康检查通过（UP）
- [ ] 冒烟测试通过
- [ ] 核心链路通
- [ ] 降级链路通
- [ ] 有回滚预案
