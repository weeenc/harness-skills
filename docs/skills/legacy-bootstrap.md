# 老系统冷启动 — legacy-bootstrap

> **技能标识**: `legacy-bootstrap`
> **使用场景**: "把一个老项目接入 Harness 研发体系"——代码库历史复杂、文档完整度不一、业务知识大量存在人脑中
> **定位**: 老系统接入 Harness 的启动技能，配合 `/apply-harness` 的棕地模式使用。核心原则：**不等待知识库完善才开始用，在每次需求迭代中滚动完善，形成知识飞轮**

## 它做什么？

把存量代码与散落资料**关联**进工作空间，再从代码与凌乱资料中**清洗**出结构化知识，最后用采访稿补齐只存在人脑中的业务知识。

## 什么时候用？

- 已有代码库，要接入 Harness 研发体系
- 知识分散在多个仓库、文档、人脑中，文档完整度不一致
- 需要从存量代码/资料中提取结构化业务知识

## 四步接入流程

### Step 1: 关联代码仓库（Git submodule）
把相关代码仓库通过 Git submodule 关联到 `src/`：关联而不复制，按业务域分目录挂载。

### Step 2: 挂载原始材料（raw/）
把已有产品文档、设计稿、接口文档、历史笔记**未经改写**地挂到 `raw/`，保留来源元数据。

### Step 3: 清洗 SKILL（从代码/资料抽取知识）
- 从代码挖业务规则 → `.harness/wiki/`
- 从代码/架构推链路 → `.harness/tech/`
- 严格遵守 `.harness/rules/知识库治理规则.md`（不复制代码、来源必填、相对路径链接）

### Step 4: 采访稿补齐人脑知识
用访谈转录工具采访核心开发/产品，把只存在人脑的规则与历史决策整理进知识库。

## 为什么需要它？

| 问题 | 解法 |
|------|------|
| 老项目文档陈旧、业务规则在人脑 | 采访稿补齐隐性知识 |
| 存量代码与 Harness 工作空间割裂 | submodule 关联 src/，不复制 |
| 冷启动无从下手 | 四步流程：关联 → 挂载 → 清洗 → 采访 |
| 等知识库完美才肯开始 | 知识飞轮：每次迭代滚动完善 |

## 完成标志

- `src/` 已 submodule 关联相关仓库，`raw/` 已挂载原始材料
- 清洗 SKILL 已产出首版结构化知识（wiki + tech）
- 采访稿已整理进知识库，术语已进 CONTEXT.md
- 知识缺口清单已登记，交由后续迭代滚动补齐
