# 知识健康检查 — knowledge-health

> **技能标识**: `knowledge-health`
> **使用场景**: "知识库体检"——扫描 `.harness/wiki/` 与 `.harness/tech/`，检测重复、冲突、失效链接、无来源结论
> **定位**: 只读检测 + 产出修复清单的技能，按 `.harness/rules/知识库治理规则.md` 执行。修复动作在清单中标注，重大裁决留人

## 它做什么？

扫描 `.harness/wiki/` 与 `.harness/tech/`，处理迭代积累的知识库病灶。

## 什么时候用？

- 定期（每迭代 / 每月）知识库体检
- 发现 Agent 检索到矛盾或过时的知识
- 知识回流（archive.md）后核对一致性

## 检测项

| 病灶 | 检测方法 | 处理 |
|------|---------|------|
| 重复主题 | 按 title / category 聚类，同概念多份文档 | 建议合并 |
| 冲突 status | 同一事实两份文档结论相左 | 追查 source 裁决 |
| 失效链接 | 扫描相对链接指向不存在的文件 | 修复或标记废弃 |
| 无来源结论 | frontmatter 缺 `source` 字段 | 补齐来源或删除 |
| 复制代码 | 文档大段重述方法逻辑 | 删实现描述，只留链路位置 |

## 执行流程

1. **收集**：列出 wiki/tech 下所有知识文件（含 frontmatter）
2. **逐项检测**：按病灶逐文件/跨文件检测，记录文件路径 + 证据 + 建议修复
3. **出体检报告**：写 `.harness/retro/knowledge-health-<日期>.md`（总览 + 修复清单）
4. **修复**：🟡 机械可修自动修；🔴 需裁决（冲突/合并）列选项请人类决策

## 为什么需要它？

| 问题 | 解法 |
|------|------|
| 迭代积累重复/矛盾知识 | 定期扫描去重、裁决冲突 |
| 文档链接失效、来源缺失 | 失效链接 + 无来源检测 |
| 知识库越滚越乱 | 体检报告留证据，🟡 自动修、🔴 留人裁 |

## 完成标志

- 体检报告已落盘，含总览 + 修复清单
- 🟡 项已修复并报告，🔴 项已列选项交人类
