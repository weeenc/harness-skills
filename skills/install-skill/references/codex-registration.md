# Codex 技能注册：按可见范围检查

由 `install-skill` 在当前宿主为 Codex 时读取。新项目入口使用 `<项目根>/.agents/skills/`；`.harness/skills/` 仍是项目运行技能的事实源。不要把原始包再次复制到项目或个人技能目录。

## 1. 建立当前作用域清单

Codex 会读取项目和个人范围的技能，同名项不会自动合并。对每个目标根单独收集：

- 从该 cwd 到其 Git 根之间的 `.agents/skills/`，以及当前会话实际提供的其他技能来源；
- `~/.agents/skills/`；已有 `.codex/skills/`、`$CODEX_HOME/skills/` 或插件入口如被当前宿主加载，也纳入检查，但不向旧目录新增副本；
- 用户配置中已禁用的入口不算可用。无法确认是否启用或是否被扫描时标记待核验，不能仅因磁盘上存在就跳过必要注册。

协调层没有 Git 时，检查它自己的项目目录与实际可见的用户来源，不向整个主目录无限向上扫描。独立 Git 子仓的扫描边界单独计算，不假定其会继承协调层技能，也不把兄弟仓库中的同名技能当作可复用入口。

递归读取扫描位置中的 `SKILL.md`（原始包可能含嵌套 skills）。记录 frontmatter `name`、作用域、入口路径和解析后的实际路径。跟随宿主支持的链接读取内容并防止循环，但不同入口即使指向同一目录也要记录，不能假定宿主一定会去重。

## 2. 比较完整内容与引用

按 frontmatter `name` 匹配，不按显示标题或源目录名判断。比较整个技能目录的文件集与内容，包括 scripts、references、assets、agents 元数据；可忽略 `.DS_Store` 等操作系统杂项，但不能只比较 `SKILL.md`。同时检查相对引用是否能在已有位置解析、技能是否依赖当前项目的渲染参数。

仅当内容一致、引用有效且当前作用域可用时才复用个人或项目入口。不能用未经渲染的 `coding-skill{{LANG_TAG}}` 替代项目的 `coding-skill-java`，也不能把名字相同但版本不同的通用技能视为等价。

## 3. 决定注册动作

| 当前作用域中的同名入口 | 动作 |
|---|---|
| 没有可用入口 | 完整复制到项目 `.agents/skills/<name>/`；若该路径已被禁用或被不同内容占用，先报告该冲突，不自动启用或覆盖 |
| 只有一个，内容与引用均相同 | 复用，记录来源路径，不再复制 |
| 只有一个，但内容不同或引用失效 | 保留双方，报告差异与影响；暂停该技能注册，继续无冲突项 |
| 已有多个同名入口 | 报告历史重复及所有路径；不再增加入口，不声称已去重，即使其中一份与源相同 |

同名不同内容时，不擅自改名或禁用个人版本。若用户选择项目定制名称，需要同步相关调用引用并重新验证；若选择清理安装范围，先核对差异与其他项目影响。默认注册流程不执行这两类迁移。

同一语言的两个独立仓库可各自在本仓注册 `coding-skill-java`。协调层通过仓库路径调度，不把它们集中注册到父目录。跨仓前后端分别使用渲染后的 `*-front` 和 `*-java` 等名称，所有注册目录均与实际名称一致。

## 4. 验证并报告

重扫当前作用域，逐个源技能核对：可用入口、解析后的名称、支持文件、未解决冲突。分别报告新增、复用、冲突、失败及对应路径。重复执行应复用上次成功创建的入口，失败项可单独重试。

目录检查能证明文件与命名关系，不能代替 UI 加载验证。宿主提供技能列表时检查列表；没有实时刷新能力时明确需要重新加载后确认，不宣称已看到命令菜单去重。

依据：[OpenAI Codex skills 文档](https://developers.openai.com/codex/skills/)（2026-10-29 核对）。技能加载规则变化时重新核对来源与边界，不以目录改名、显示名称改名或“项目同名会覆盖个人”的假设解决冲突。
