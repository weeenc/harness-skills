# 编码规范

> **作用域**: 本项目全模块 Rust 代码标准与约定。
> **基线**: Rust API Guidelines + rustfmt + Clippy。
> **状态**: 强制 · 由 `cargo fmt --check` + `cargo clippy -- -D warnings` 机械化检查

---

## 1. 命名约定

| 元素 | 规则 | 示例 |
|------|------|------|
| 变量/函数/方法 | snake_case | `calculate_total_cost` |
| 类型（struct/enum/trait） | PascalCase | `RoutePlanningService` |
| 常量 | SCREAMING_SNAKE_CASE | `MAX_CALL_DEPTH` |
| 模块 | snake_case | `route`, `service` |
| trait 方法 | snake_case | `fn estimate(&self, ...)` |
| 测试函数 | `#[test]` + 描述性名称 | `fn test_calculate_total_cost()` |
| 泛型参数 | 大写单词 | `T`, `E`, `Item` |
| 类型参数顺序 | T / E / R 等约定俗成 | `Result<T, E>` |

- 禁止拼音与英文混用、禁止无意义缩写（`a1`、`tmp2`）。
- 禁止魔法值：所有字面量定义为 `const` 或枚举。

## 2. 注释与文档

- **所有 `pub` 项必须有 doc 注释**，以 `///` 开头
- crate 必须有顶层 `//!` 文档注释
- 复杂逻辑用行内 `//` 注释解释**为什么**，而非**做什么**
- `TODO` / `FIXME` 必须转化为 `.harness/changes/` 中的任务条目

```rust
/// Evaluate 评估给定请求并返回结构化结果。
/// 当数据缺失时返回保守默认值。
pub fn evaluate(request: &Request) -> Result<EvaluationResult, AppError> {
    // ...
}
```

### 2.1 导入规范
- 导入顺序：标准库 → 第三方 crate → 本地模块，每组空行分隔，`cargo fmt` 自动整理
- 禁止通配导入（`use xxx::*`），除非测试模块
- 用 `pub use` 收敛对外 API

### 2.2 日志级别约定
| 级别 | 用途 |
|------|------|
| Debug | 开发调试细节 |
| Info | 关键流程节点 |
| Warn | 降级、重试、限频命中 |
| Error | 需人工介入的失败 |

结构化日志（`tracing`），含 `timestamp / level / trace_id / message / context`。

## 3. 错误处理

| 规则 | 说明 |
|------|------|
| 不吞错误 | 禁止 `let _ = ...;`、`unwrap()`、`expect()` 吞错误（测试/启动代码除外） |
| 错误分层 | 用 `thiserror` 定义枚举错误类型，避免裸 `String` |
| 错误包装 | 用 `?`（`From` 实现）向上传播并带上下文 |
| 错误信息 | 包含上下文，但**禁止泄露密钥/隐私** |

```rust
// ❌ 禁止（业务逻辑中）
let resp = client.call(req).await.unwrap();

// ✅ 正确（业务逻辑中）
let resp = client
    .call(req)
    .await
    .map_err(|e| AppError::ExternalTimeout { source: e })?;
```

## 4. LLM / 外部调用约束（强制）

每一次 LLM 或外部 API 调用必须具备：

| 维度 | 要求 |
|------|------|
| 超时 | 30s（`tokio::time::timeout` 或 `reqwest` client timeout） |
| 重试 | 3 次，指数退避（1s / 2s / 4s） |
| 限频 | 按业务场景配置 |
| 降级 | 必须有默认值/缓存/离线估算，禁止裸抛到用户 |

### 4.1 统一外部调用治理
- 外部调用能力必须尽量收敛到统一封装层，禁止每个模块各自散写一套超时/重试/限频/降级。
- 同一外部依赖在项目内应只有一套主治理策略。

## 5. 空值安全与防御式编程

- public 函数入参做范围校验（返回 `Result`）。
- 可选值用 `Option<T>`，禁止用哨兵值（`-1`、"not found" 字符串）模拟空值。
- 禁止裸 `as` 强转；用 `try_from` / `From` 安全转换。
- 索引访问用 `get()` / `get_mut()` 返回 `Option`，避免 Panic。

---

## 6. 并发与状态（tokio / std threads）

- 共享状态走 `Arc<AppState>` / Redis / 缓存，禁止全局可变变量持有业务状态。
- 异步任务必须明确生命周期，`tokio::spawn` 的句柄要管理（JoinHandle），避免泄露。
- 限制并发用 `Semaphore`，禁止无界 unbounded 队列积压。
- `unsafe` 代码必须经过 ADR 审批，并附带 `// SAFETY:` 注释说明不变量。

---

## 7. 安全红线

| 红线 | 规则 |
|------|------|
| 密钥 | API Key/Token/密码 → 环境变量 或 配置中心，**禁止硬编码** |
| 日志 | 禁止打印 Token、密码、用户隐私 |
| 输入校验 | 所有外部输入必须校验后使用 |
| unsafe | 禁止使用 `unsafe`（除非经 ADR 审批 + SAFETY 注释） |
| 依赖 | 上线前 `cargo audit` / `cargo deny` 无高危漏洞 |

## 8. 代码质量量化指标

| 指标 | 阈值 | 守护 |
|------|------|------|
| 文件长度 | ≤ 800 行 | cargo clippy / 人工 |
| 函数长度 | ≤ 50 行 | cargo clippy |
| 圈复杂度 | ≤ 10 | cargo clippy |
| 核心逻辑覆盖率 | ≥ 80% | `cargo llvm-cov` / `cargo tarpaulin` |
| 未使用代码 | 禁止 warning | cargo clippy -D warnings |
| 格式 | rustfmt 规范 | `cargo fmt --check` |
| 依赖漏洞 | 0 高危 | cargo audit / cargo-deny |

## 9. 测试优先编码约定

- 核心业务逻辑、业务规则判断、降级策略默认采用测试先行。
- 每条 AC 应有对应测试映射；每条关键降级路径应有专门测试。
- 测试优先验证**行为与结果**，而不是实现细节。
- 用 `#[cfg(test)] mod tests` 组织单元测试，`tests/` 放集成测试。


## 11. 简单优先（YAGNI）

- 能用简单方案就不用复杂方案。
- 不为"未来可能的需求"写代码。
- 不引入大型第三方 crate 只为一个小功能。
- 不提前做宏/泛型抽象（Speculative Generality）。
## 12. 单元测试示例（unit-test-write 引用）


```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_validate_should_reject_when_value_exceeds_limit() {
        let input = input_with_value(11500);
        let result = validator.validate(&input);
        assert!(result.rejected);
    }

    #[test]
    fn test_process_should_return_fallback_when_external_service_timeout() {
        let request = new_request();
        let mut mock_client = MockExternalClient::new();
        mock_client
            .expect_call()
            .times(1)
            .returning(|_| Err(AppError::ExternalTimeout));
        let svc = Service::new(mock_client);
        let result = svc.process(&request);
        assert!(matches!(result, ProcessResult::Fallback { .. }));
    }
}
```
